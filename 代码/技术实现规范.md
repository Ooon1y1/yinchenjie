# 《隐尘劫》技术实现规范

> 文档状态：技术实现基线 v2.2（2026-11-05 补录血瓶机制；v2.1 于 2026-11-02 拆分自 v2.0 总案）
> 引擎：Godot 4.7.2（唯一开发与发布引擎版本，不为其他引擎维护并行实现）
> 用途：AI 辅助开发专用（生成 GDScript、配置数据直接参照）
> 上层约束：`../策划/玩法策划.md`（策划§x，数值与规则以该文档为准）
> 关联文档：`../美术/美术音频规范.md`（美术§x，资源产出规范）

## 1. 核心节点方案

- 玩家 / 敌人：`CharacterBody2D` + `AnimationPlayer` + `Sprite2D`
- 攻击判定：`Area2D` + `CollisionShape2D`，攻击帧激活，结束回收；🆕 连招中动态修改 `CollisionShape2D` 的 `shape.size` 与 `position`（按 ComboData 的 `attack_range` / `attack_offset`，见 §4）
- 敌人寻路：`NavigationRegion2D` + `NavigationAgent2D`
- 背景：`Parallax2D` 多层视差（远山、云雾、前景）
- 全局管理：AutoLoad 单例脚本

## 2. 核心脚本结构

1. `PlayerController.gd`：玩家状态机、输入处理；🆕 攻击输入转发至 `ComboManager`，状态机新增 `combo_1` ~ `combo_n`、`derive`、`finisher`、`weapon_switch` 状态
2. 🆕 `ComboManager.gd`（挂载玩家节点）：当前连招段管理、连击计数、输入缓存（0.2 s）、取消窗口检测、派生 / 终结逻辑；读取 `combo_data.gd` 配表动态加载攻击参数
3. 🆕 `combo_data.gd`（AutoLoad）：ComboData 全量配表（字段见 §4）
4. `CombatComponent.gd`：攻击、受击、格挡、弹反通用组件
5. `BuffManager.gd`（AutoLoad）：词条增删、属性叠加计算；🆕 扩展：解锁类词条动态向连招池追加可用派生 / 段数（`unlock_combo_id` / `unlock_flag`），强化类实时修改连招伤害、范围、硬直参数（见 §5）
6. `EnemyBase.gd`：敌人通用状态机、寻路、攻击逻辑；🆕 新增浮空 / 眩晕 / 减速受击状态处理
7. `RoomManager.gd`：房间状态、敌人生成、传送门逻辑
8. `GameManager.gd`（AutoLoad）：全局进度、局内数据、死亡重置；🆕 最高连击统计、已持有武器列表；🆕 血瓶次数 `flasks` 与 `use_flask()` / `refill_flasks()` 接口（数值见策划§2.11）

## 3. 连招状态机架构（🆕 v2.0 核心）

1. 每一段普攻为独立状态（`combo_1` ~ `combo_n`），播放对应动画，到判定帧激活攻击盒
2. 输入缓存：0.2 s 内提前输入下一次轻击 / 重击，到可衔接帧自动触发下一段
3. 取消检测：后摇阶段检测闪避 / 跳跃输入，符合取消窗口条件则强制切换状态；命中瞬间检测 K 输入触发派生取消
4. 连招计数器：全局记录当前连击段数与连击数，切换武器 / 受击 / 超时重置
5. K 键分流：`combo` 状态中短按（< 0.15 s）→ 派生 / 终结；非 combo 状态按住（≥ 0.15 s）→ 蓄力重击

## 4. ComboData 连招段配表（`combo_data.gd`）

各武器与招式的数值（伤害、判定、消耗、触发条件）以策划§3 为准，本节定义其落库字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| combo_id | String | 连招段唯一 ID（如 `changjian_1`、`changjian_derive_shangtiao`） |
| weapon_id | String | 所属武器（`changjian` / `zhongjian` / `duanren` / `changge`） |
| combo_type | Enum | `normal`（普攻）/ `derive`（派生）/ `finisher`（终结） |
| combo_index | Int | 连招段序号（派生技记录其挂载的普攻段） |
| damage | Float | 伤害值 |
| attack_range | Vector2 | 攻击盒尺寸（px） |
| attack_offset | Vector2 | 攻击盒中心偏移（px，正 x = 面向前方） |
| pre_frames | Int | 前摇帧数（60 FPS 逻辑帧，0.06 s = 4 帧） |
| active_frames | Int | 攻击判定帧数 |
| post_frames | Int | 后摇帧数 |
| cancel_window | Int | 可取消的起始帧（后摇取消 = post_frames × 50%；派生取消见各武器窗口） |
| knockback | Float | 击退力（px/s） |
| stun_time | Float | 敌人硬直时间（s） |
| cost | Int | 内息消耗 |
| is_unlocked | Bool | 是否需要词条解锁（true = 需对应 unlock_combo_id 词条） |
| animation_name | String | 对应动画名 |

## 5. 词条配表结构（`entries_data.gd` / `buff_manager.gd` 参照）

### 5.1 ENTRIES 配表示例

```gdscript
# entries_data.gd — 词条配表（AutoLoad）
const ENTRIES := {
    # v1.1 词条保留原结构，新增 category 字段
    "xun_ci": {"name": "迅刺", "school": "swift", "category": "buff", "desc": "轻击攻速+15%，连招窗口+0.1s", "price": 50},
    # ……
    # v2.0 解锁类词条新增字段
    "xing_yun": {"name": "行云", "category": "unlock", "desc": "解锁跳跃取消", "price": 50,
                 "unlock_combo_id": "", "unlock_flag": "jump_cancel"},
    "cs_shang_tiao": {"name": "长剑・上挑", "category": "unlock", "desc": "解锁上挑派生", "price": 50,
                      "weapon_id": "changjian", "unlock_combo_id": "changjian_derive_shangtiao"},
    # v2.0 强化类词条新增字段
    "po_shi": {"name": "破势", "category": "buff", "desc": "派生技伤害+25%", "price": 50,
               "combo_damage_mult": {"derive": 0.25}},
}
```

词条 ID、名称、效果与定价以策划§4 为准，本节定义其落库字段。

### 5.2 BuffData 新增字段（v2.0）

- `category`：`unlock` / `buff` / `mechanic` / `effect`（对应策划§4.1~4.4 四类）
- `weapon_id`：武器专属词条的归属武器
- `unlock_combo_id`：解锁的连招 / 派生 ID（解锁类）
- `unlock_flag`：解锁的功能开关（如 `jump_cancel` / `air_combo` / `pre_swing_derive`）
- `combo_damage_mult`：分招式类型的伤害倍率（如 `{"normal": 0.15, "derive": 0.25, "finisher": 0.30}`）
- `cancel_window_bonus`：取消窗口加成（秒）
- `hit_effect`：命中附加效果 ID（如 `frost` / `explode` / `lifesteal` / `guard_break`）

## 7. 补充技术约定与性能要求

- 像素完美渲染：项目设置中纹理过滤 `nearest`，视口缩放开启 snap，禁用抗锯齿
- AutoLoad：`AudioManager`（BGM 切换 / 音效播放）、`PoolManager`（剑气 / 飞剑 / 毒弹 / 特效对象池）
- 信号解耦：房间清空、词条拾取、玩家死亡、🆕 连击变化（`combo_changed(count)`）、🆕 武器切换（`weapon_changed(weapon_id)`）、🆕 血瓶次数变化（`flasks_changed(current, max_uses)`）等跨模块事件走全局信号总线，禁止节点间硬引用查找
- 剑气、飞剑、特效使用对象池，禁止频繁「实例化 / 销毁」
- 同屏敌人不超过 6 只，保持帧率稳定
- 🆕 连招判定盒复用单一 `Area2D`，仅动态修改形状与位置，不为每段新建节点
